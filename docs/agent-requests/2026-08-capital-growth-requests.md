# Agent request spec — Aug–Oct 2026 capital + growth sprint

This file records information/actions the operating agent must request rather than guess.

## Owner inputs

1. **Final use of funds**
   - Owner supplies categories and amounts.
   - Do not treat any older preliminary allocation as final.
   - Once supplied, propagate consistently into the capital model, Wefunder materials, Shared Capital/Groove/MCCD packets, and any grant/lender application.

2. **Wefunder security decision**
   - Present co-op-compatible options with economics and dilution/control implications.
   - Current unresolved contrast: older 6% cumulative-return concept versus later 8% accruing convertible-note concept.
   - Do not publish terms before owner selection and securities counsel/Wefunder confirmation.

3. **External communication approval**
   - Follow `AGENTS.md`: exact dry-run through the exact channel, then explicit owner approval naming real recipients.

## Financial evidence the agent must obtain

- Current unrestricted business cash.
- Fresh Local Budget actuals.
- Current Square Capital payoff balance.
- Complete debt schedule.
- AP and aging.
- AR and aging.
- Tax liabilities/status.
- Final founder draw/deferred-comp reconciliation.
- Current balance sheet / lender-ready pro forma outputs.

Use Capital Master Record v2.3 as the financing source of truth for definitions and evidence hierarchy. Do not copy the full record into this public repository.

## Planner / operator requirements

- Reconcile existing Planner state before applying the seed.
- Do not duplicate equivalent cards.
- Preserve completed cards.
- Keep customer PII and private correspondence out of repo source.
- Pull exact customer/event details from Gmail/internal systems when executing the card.
- Report each material workstream as `done`, `blocked`, or `next` at handoff.

## Completion standard

A workstream is not “done” because a memo exists. It is done when the next operational dependency is satisfied—for example, an application packet is complete, a proposal is submitted, a meeting is scheduled, or a model has current inputs and can support the next decision.
